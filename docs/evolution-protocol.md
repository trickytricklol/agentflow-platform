# 工作流自进化：冻结实验协议

## 问题与算法

学习对象是工作流 classify 节点的指令，模型权重和 DAG 不变。业务规则作为不可修改的输入，所有实验臂获得相同规则。

执行路径：start → classify（真实 Ollama）→ end → 严格奖励 → 训练失败轨迹 → 模型反思生成三个候选 → 随机或 GP/EI 选择其中两个 → 再执行。重复两轮，在验证集选版本，严格优于基线才生成发布版本和回滚 DSL。

设计参考 [ProTeGi](https://arxiv.org/abs/2305.03495) 的失败反馈及 [GEPA](https://arxiv.org/abs/2507.19457) 的轨迹反思。这里是独立的简化实现，不是论文算法复现。GP/EI 为现有实现；词法 TF-IDF 只作为 embedding 消融基线。

## 固定条件

- 模型 qwen3:1.7b，temperature=0，max_tokens=160；所有执行臂相同。
- 12 train / 12 validation / 24 test，自建模拟工单，不冒充真实客户日志或公开 benchmark。
- 奖励：最终响应须解析为仅有 route、priority 的 JSON，两个字段全对才得 1 分。思考标签被剥离，截断思考响应不得分。
- 每个搜索臂 4 个新候选 × 12 条训练样本；每轮只评估 3 个候选中的 2 个，保留真实选样决策。
- 每臂最多两个训练候选进入验证集；测试集只在两臂选定后执行。
- 训练错误可以给变异模型看，验证/测试样本及答案不进入变异请求。
- 固定基线、随机反馈搜索、GP/EI 反馈搜索。测试逐样本交错执行以缓和顺序效应。
- 逐条保存原始输出、节点事件数量、状态、错误、输入/输出 token、墙钟延迟；保存候选谱系和反思文本。

## 效果解释

优先报告独立测试任务成功率；同时记录格式率、优化期总 token 和执行成本。小样本给出置信区间，不把一次胜出推广为稳定优势。不以更换模型产生的收益冒充搜索算法收益。不根据 test 结果继续选择同一测试集上的版本。

随机和贝叶斯搜索可能进入不同候选谱系；这比较完整算法效果。要单独证明 EI 的因果贡献，还需固定候选池、多随机种子与相同预算的选样消融。

首次实验失败或无提升必须保留。只在训练集失败反馈上生成候选，验证集用于选版；测试结果用于最终分析，不能反向用于本轮调参。多轮探索已重复使用同一测试集，跨实验结论只能视为探索性结果，不能视为一次未接触的最终留出验证。

## 结构进化扩展（structure-v1）

进化基因包含 `topology` 和 `prompt`：direct 单节点决策、decompose 路由/优先级双专家与汇总、review 初判与复核。执行器实际构建不同 DAG，并保存每个模型节点的输出与费用；没有用答案驱动节点或硬编码标签。分工分支目前串行调度，以控制单 GPU 竞争，不声称并行加速。

从初始训练失败生成三个指令变异，附加训练失败示例；与三个拓扑交叉，去掉原始基线后得到 11 个候选。两种搜索使用同一个候选池和神经向量，分别采样四个候选，使用最多两个候选的验证结果选择是否发布。平分时优先 Token 更低，但发布仍要求严格准确率增益。

这里对齐的是候选评估次数，不是模型调用数：双节点拓扑费用更高。报告必须呈现模型调用数、训练/验证 Token 与测试 Token，不能将效果提升称为免费增益。只搜索受限拓扑模板，尚非任意图结构生成或自主主从任务规划。

## 策略锁定与选样审计扩展

生成策略放入明确的 advisory 区域，immutable policy 始终优先。候选若缩窄、遗漏或冲突业务规则，执行器必须采用原策略。该变更后重新跑完整实验，不与旧提示拼接方式直接合并统计。

选样审计固定一次 4B 产生的 11 个候选，先建立全候选训练得分表，再离线重放四次评估预算。随机基线枚举全部 `C(11,4)=330` 个子集，得到精确的命中最优概率；GP 分别使用纯文本向量和预先固定权重 0.35 的文本+拓扑向量。建立全表的 Token 是审计成本，不冒充某条在线搜索轨迹的成本。该实验只验证单个候选池内的 acquisition 行为，不验证测试泛化。

## 文献启发扩展

- GEPA 风格：实例或 case×objective Pareto 前沿、互补覆盖父代、训练轨迹反馈、系统感知 merge、二次策略审计、mini-batch 预筛。最终仍以完整训练和验证发布，不允许 mini-batch 直接上线。
- MIPRO 风格：从训练集产生空/标签覆盖/失败优先/随机四类 demo set，与去除旧示例的 instruction 组合。随机和 GP/EI 使用同一候选池与六次评估预算。
- 风险发布：候选须在三个匹配种子的验证执行中逐次不退化、平均严格提升，并在 route 与 priority 的所有业务切片上不退化。风险门控只使用 validation，不读取 test/confirmation。
