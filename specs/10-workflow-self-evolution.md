# 子规格 10：工作流自进化

## 目标

把执行失败转化为下一代可执行工作流，而不是依赖人工修改提示词。系统需要完整记录失败、候选生成、预算选样、结构变化、验证决策与回滚版本。

## 候选模型

```text
genome = (topology, instruction, demo_ids, tool_config)
```

- `topology`：`direct`、`decompose`、`review` 三种受限模板。
- `instruction`：基线指令或失败反馈生成的候选指令。
- `demo_ids`：训练集示例组合。
- `tool_config`：白名单内的工具配置。

## 流程

1. **严格奖励**：输出必须是仅含 `route`、`priority` 的 JSON，两个字段全对才得 1 分；自然语言目标只映射到白名单奖励配置。
2. **失败归因**：逐子项诊断格式、`route`、`priority`，记录实际值与期望值。
3. **反馈变异**：训练失败进入反思模型生成候选；保存父版本、失败 ID、反思原文与重试错误。
4. **有限预算选样**：神经嵌入 + RBF 高斯过程 + Expected Improvement，只评估候选池中的有限子集。
5. **结构搜索**：指令与拓扑模板交叉组合，候选通过 DAG 校验后真实执行。
6. **验证发布**：训练集用于搜索，验证集用于发布，测试集只用于报告。
7. **版本产物**：发布时保存完整新 DSL 与原始回滚 DSL。

## 发布门

候选必须同时满足：

- 验证集整体指标严格优于当前版本。
- `route` 与 `priority` 每个业务切片不退化。
- 多次匹配种子重复验证均不退化。
- 冻结确认通过；失败则记录拒绝原因并回滚。

## 产物

| 文件 | 内容 |
|---|---|
| `report.json` | 候选谱系、逐条输出、Token、延迟、验证与发布决策 |
| `confirmation.json` | 冻结版本确认结果与文件哈希 |
| `release.json` | 发布/拒绝原因与回滚 DSL |
| `analysis.md` | 可读汇总 |

## 安全约束

- 不执行模型生成的代码，只允许白名单 DSL 与拓扑模板。
- 不可变业务策略优先于候选指令；冲突时采用原策略。
- 测试集与确认集不参与候选选择。
- 发布失败必须保留当前版本，不允许覆盖线上版本。

## 验收

- 单测覆盖字段评分、非法 JSON、奖励白名单、采样预算、训练示例范围、拓扑变更、复核、切片门控与回滚。
- 本地 Ollama 完成端到端执行，所有节点使用真实 Provider。
- 发布产物可被 `evaluation/verify_evidence.py` 重新计算与校验。

实现与运行方式见 [docs/optimization.md](../docs/optimization.md)。
